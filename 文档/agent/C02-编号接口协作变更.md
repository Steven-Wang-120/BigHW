# C02 编号 接口 协作与变更

编号唯一来源根《要做什么》：FR-01–32、CR-01–10、NFR-01–03、NR-01–06；用例TC-01–48；模块M1–M4。已存在编号不重排；废弃保留原因。自查设计计数不是实现实测。

## 协作边界

domain纯规则无IO，services协调权限/事务/版本，repository持久化，web调用service不直接SQL；原生HTML/JS/CSS同源Fetch，无前端Node构建/框架/Jinja，不豁免B01课程工具环境核验。先固定身份/角色/对象契约，B05用受控actor域/服务测试，B06独立实现会话后集成，不互为阻塞。HTTP普通body JSON、imports/pipeline multipart FormData自动boundary、export CSV，JSON/form/query未知字段422；API错误体error.code/message/details与request_id，金额/大数量字符串，expected_version乐观更新。

## 变更流程

1. 读相关根FR/CR+具体B/TC/契约，记录当前版本和未提交工作。
2. 写原因/证据、方案、影响编号/接口/schema/数据/性能；普通范围内可逆修正自主做，不造审批门。
3. 新的用户选择或基线冲突交协调端，保守vs时间优先未答不擅自记D-03；90天/四位是建议不是官方。
4. 先更新根规格，再同步接口schema/API、B步骤、C禁区、测试断言、自查计数和Word说明；不得只改算法名。
5. 数据规则变化提升normalization/matching version，保留旧run不伪覆盖；原文件与源身份保持，快照变化新hash。
6. 运行真正相关测试和回归，失败/未执行诚实记录；Word内容变重渲染逐页看。
7. 交接diff/路径/影响编号/真实命令/结果/未完成，保护用户未提交文件；禁止并发修改同一工作区或他人的Git状态，正常独立worktree可按协调安排使用，不将共享Git元数据一概禁止。

## 事务优先次序

login豁免既有CSRF但先验配置同源Origin→字段/凭据；其它请求会话身份（失效先401）→变更Origin/CSRF→角色→结构字段→对象范围→领域；Origin缺失/null/异源403。Assign先ALREADY_ASSIGNED（显示当前人）再expected_version→状态/领域字段；其它更新先version再流转。纯domain未派单start为NOT_ASSIGNED，HTTP可能先403/404。成功日志失败业务回滚；拒绝日志独立失败明确未留痕。

会话双Cookie、稳定token和hash验证以契约/B06为准，me仅user不恢复token；TC-41.a–l/TC-45.a–c须逐例验证。pipeline导入SUCCESS/run失败保留batch_id/run_id/attempt/retry_action=POST_RUNS，JSON POST /api/v1/runs以同batch同规则重试同run/attempt+1，不重传。行非有限/64位溢出主INVALID_NUMBER_OR_DATE（溢出加NUMERIC_OVERFLOW），超精度另码；累计lot/run超界为run FAILED不改行裁决。R1 N=outside+selected与selected=sale+cancel+excluded（excluded已第三类）、match/work分离、assignment unique、未来纯合成fixture Git白名单均不得静默删。
