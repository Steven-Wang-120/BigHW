# C03 测试证据真实性

本轮48个TC是计划，全部未执行；docx结构/渲染、链接/编号检查不是业务测试。≥10真实自动化、用户亲手复跑、独立测试agent和核心code review待未来施工。

## 每条证据必须能复核

记录TC/FR、输入类别F或R/hash/范围、源码commit或未提交状态、规则版本、硬件OS/依赖、完整命令、起止/退出码、实际数值/状态/code和原输出路径。失败/中断/跳过分别标，不删失败图，不把未执行写passed。不借课程样例当项目测试/截图/用户决定。

F受控fixture可用于清楚标注的单元/集成/并发/API/浏览器受控边界测试与演示，明确纯合成且不进raw，不把F当真实R；唯一未来Git白名单controlled_cases.json随消费测试真实提交支持bundle复现，其它输出继续ignore，不摘录真实流水。本轮不创建。R唯一官方源派生快照。真实性能3独立空库冷数据每次≤5秒，解析/规范/导入/匹配/差异到摘要可读都计入；抽取/启动/下载另列。query每次≤2秒，真双连接竞争各10轮，不能用顺序或平均掩盖。原始数据无真实原单外键，不用推断配对率叫准确率。

## 修改测试

规则需求改动才合法改期待，说明旧断言为什么错/新编号影响并同步根/B/Word；不是红灯就降低门槛或删用例。外键unique/失败rollback/审计注入/权限与对象范围需真实验证。不使临时测试操作触碰用户库/原件。

## 过程

用户亲敲与agent代跑分开记录；第三设计决定待答，不能为了≥3伪造。日记只真实日期，没commit明确无，没截图明确无；不能造hash/改系统时间/未来日期/8日空目录。技能须重启后真调用，Hook用隔离目标真拦截，不改全局审批。未发生就是待完成，不要求学生编三个失败故事。
