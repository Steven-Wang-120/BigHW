# C01 数据语义禁区

## 已有事实

唯一官方UCI raw zip/xlsx；Chen D.(2012)、CC BY4.0。实际两表Year 2009-2010/2010-2011表头Invoice/Price/Customer ID映射课程InvoiceNo/UnitPrice/CustomerID，详见manifest。当前只每表1000数据行抽样；dimension合计1067371不是全量扫描确认。

## 禁区

- raw/课程原件与课程脚本不改不运行；不重下；不把数据混入文档/课程原件/程序；不输出逐行交易至Markdown/docx。
- 两边是正向/取消视图，年度表不是财务与仓库两账；取消新单号不指向原单，配对是规则推断，不说真实原单/准确率。
- 未来真实10k建议sheet2010-2011行2–10001，不预过滤/去重/随机补样；源SHA/sheet/行身份保留，截断发票标flag；百万N由完整值扫描，原N=outside+selected和selected=sale+cancel+excluded分别展示，excluded已第三类不能双加。
- 行裁决互斥穷尽；主排除首原因一个、次flags不重复计排除。缺客户/描述/国家保留，缺客户取消不配；商品合法字母不可强转数，描述不作键。
- 价Decimal四位单位/1e-9尾差支持建议需B02全量验证；≤0/真实超精度排除计数，不静默损失；TC-05/14拒NaN/±Infinity主INVALID_NUMBER_OR_DATE，行数量/规范价/金额/取消绝对量64位溢出同主码+NUMERIC_OVERFLOW；累计lot/run超界令run FAILED不改行裁决。整数计算、JS不浮点对账，尾差恰等/略超有子例。
- 同内容不同源行不静默删除；疑似重复抑制自动配对。保守算法待确认（用户已问含义并获解释，不是完全未答）；90天窗口非官方，版本固定；不跨lot/最近时间抢配/累计超量。
- 关闭工单不是配对成功；不改流水/金额/匹配状态。受控fixture只未来明确边界测试，不替代真实快照/伪装第二账。

## 发现冲突怎么办

源hash不符、真实高精度、分母/位置不可靠、范围截断或国家异常先保留只读聚合证据，向协调端报告；不通过改raw/减行数/换算法静默解决。规则改变同步C02，hash/范围不同时性能不能直接比较。
